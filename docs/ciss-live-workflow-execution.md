# CISS 中文交互式问诊工作台：执行与测试计划

## 范围和停止条件

只改动 `githubpages/x_ciss/`、其测试，以及本 `docs/` 下两份文档。只在本地预览；不得提交、推送、部署、调用 Cloudflare 或修改 DNS。用户看过本地版本前，不得进行任何线上操作。

开始前完整阅读 `docs/ciss-live-workflow-design.md`。现有工作树有未跟踪的 `.DS_Store` 和文档，不能删除、暂存或覆盖。

## 核心回退清单

| 当前本地版本 | 目标版本 |
| --- | --- |
| 默认 `Live workflow` 四格总览 | 默认 `问诊` 页面 |
| `00` 总览导航与 16 秒阶段循环 | 四个中文任务导航，无全局流程循环 |
| 只读开检查 | 可搜索、勾选、检查一致性的模拟开单 |
| 只读病历 | 可编辑、复制、打印、导出的本地模拟病历 |
| 录音方格在总览 | 录音方格在问诊控制台 |
| 英文产品文案和脱敏英文患者名 | 中文文案和患者“张三” |

## 测试原则

每一阶段完成后立即运行对应测试。测试脚本必须真正以退出码 `0` 完成；不得因为截图已生成、页面能打开或先前运行过一次就宣称通过。任何浏览器自动化工具不兼容时，替换为本机可复现的方案（优先使用本项目可解析的 Playwright），而不是忽略失败。

## 第 0 步：基线与测试基础

1. 读取当前 CISS 源码、数据和 `git diff`；识别本地总览改动与此前的互动实现。
2. 保留或重写 `githubpages/x_ciss/tests/smoke.mjs`，使其能启动/使用一个本地静态服务并真实打开页面。
3. 测试必须使用兼容的本机浏览器自动化，不能继续依赖已报错的 `Page.enable` 协议路径。

### 第 0 步验收

- `node --check githubpages/x_ciss/app.js` 退出 0。
- 所有 `githubpages/x_ciss/data/*.json` 可以解析。
- 本地 CISS 首页返回 HTTP 200。
- 烟雾测试能够完成一个最小页面加载断言，退出 0。

## 第 1 步：中文与默认问诊页

1. 去除总览路由、`00` 导航、阶段计时器和四格工作流 DOM。
2. 默认页面改为问诊；导航、页面标题、患者字段、状态、按钮、弹窗、提示和可访问文本全部中文化。
3. 患者数据改为 `张三`，保留合成门诊号、科室和日期；在患者条右侧或底部保留小号“模拟演示数据”。

### 第 1 步验收

- 初次加载可见“问诊”“开检查”“查结果”“写病历”和“张三”。
- 初次加载没有 `Live workflow`、`Live case`、`workflow`、`flow` 或 `00` 总览入口。
- 静态扫描检查所有 UI 源字符串；专有名称 `CISS`、`GitHub` 是仅有允许的英文品牌词。
- 默认 hash 或路由为问诊，浏览器测试确认问诊控制台显示。

## 第 2 步：把动态方格放入问诊控制台

1. 在问诊记录顶部放置“录音输入中 · 模拟演示”状态、录音点和 12 格采集矩阵。
2. 矩阵在问诊页可见、可理解，且不挤压转写和摘要阅读区。
3. 删除总览使用的全局状态循环；仅保留问诊采集方格的有限动态。
4. 实现 `prefers-reduced-motion` 稳定状态。

### 第 2 步验收

- 浏览器测试找到问诊控制台、12 个方格和录音状态文本。
- 正常模式下在合理等待时间内至少一个方格的视觉状态/属性发生变化。
- reduced-motion 下方格状态稳定且无循环动画。
- 样式扫描确认渐变仅存在于采集方格相关选择器；页面背景、患者条、导航和普通面板没有渐变或装饰阴影。

## 第 3 步：恢复开检查参与流程

1. 恢复项目搜索、勾选、已选数量和“检查开单一致性”。
2. 恢复模拟冲突/遗漏检查和可关闭结果弹窗；所有文本中文化。
3. 明确提示为“模拟规则提示”，不显示医疗建议或不实诊断。

### 第 3 步验收

- 浏览器测试导航到开检查，能筛选列表、勾选至少一个项目，并更新已选数量。
- 未选择项目时点击检查给出中文提示；选择满足条件的项目后，结果弹窗或结果区出现。
- 关闭结果后可继续修改选择并再次检查。
- 不产生外部网络请求、存储或提交动作。

## 第 4 步：恢复结果与病历参与流程

1. 查结果页的条目、状态、图片说明和边界文本中文化。
2. 写病历页恢复可编辑草稿以及复制、打印、导出动作；生成文本和下载名使用中文。
3. 所有动作只针对当前浏览器内容；不发送数据。

### 第 4 步验收

- 浏览器测试导航到查结果，至少验证两项结构化结果和原始报告图可加载。
- 浏览器测试导航到写病历，修改文本后能触发复制/导出流程；打印使用 stub，不能真的弹出用户窗口。
- 测试确认病历动作不向网络发送请求，也不写入持久化存储。
- 所有可见的动作标签和反馈为中文。

## 第 5 步：视觉与最终本地交付

1. 以 1440×900 和 390×844 运行同一套浏览器测试并生成截图。
2. 桌面首屏要优先呈现问诊控制台、录音方格和摘要；手机端不得横向滚动。
3. 重新运行所有前序门槛和 `git diff --check`。
4. 维持一个稳定的本地预览地址；确认其路径与实际服务根目录一致后再交给用户。

### 第 5 步验收

- `node --check`、JSON 解析、浏览器烟雾测试、`git diff --check` 全部退出 0。
- 两个视口的 `scrollWidth <= innerWidth`。
- 截图中不出现英文产品文案、Live workflow、四格总览或 `示例患者`。
- 预览 URL 返回 200，且用户打开的精确路径不返回 `Not found`。
- 报告改动文件、每一项测试输出、桌面/手机截图路径和本地预览 URL；明确说明没有提交或部署。
