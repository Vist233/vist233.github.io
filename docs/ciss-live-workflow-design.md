# CISS 中文交互式问诊工作台：设计说明

## 本次决定

撤回“默认四阶段 Live workflow / 运行总览”的信息架构。CISS 不应是自动播放的流程展示页，而应恢复为可参与的静态产品演示：用户可以在模拟问诊中查看转写、选择检查项目、触发规则检查、查阅结果，并编辑、复制、打印或导出模拟病历。

保留上一版唯一有效的改动：问诊录音的方格信号。它不应放在独立的流程总览里，而应成为 `问诊` 页面最明确的工作台状态——用户打开页面就知道此处正在接收问诊语音与转写内容。

## 为什么回退总览

“Live workflow”把问诊、开检查、查结果、写病历全部压进同一块只读面板。它能说明系统链路，却有三个根本问题：

1. 用户不能参与原有的演示流程，开单勾选、规则检查和病历编辑被移除了。
2. `Live case`、循环计时和四格状态让页面像流程监控板，压过了医生实际工作的主界面。
3. 视觉重点从“医生怎样用这个系统”转成“系统怎样自我播放”。

本项目应展示一个人如何完成一次模拟门诊流程，而不是展示后台自动运行。

## 体验目标

初次打开时，用户一眼看明白：

- 这里是问诊台，正在模拟记录患者与医生的对话；
- 录音输入会被转写为结构化问诊内容；
- 下一步可以进入开检查，选择项目并查看冲突或遗漏提醒；
- 结果会回到病历，用户可以继续编辑和导出模拟记录。

“真实系统感”来自信息层级、连续的操作和反馈，不来自伪造真实病人、真实麦克风或后台服务。

## 默认页面：问诊控制台

默认路由为 `#consult`，左侧只保留四个中文导航项：

```text
CISS
临床工作台

01  问诊
02  开检查
03  查结果
04  写病历
```

页面上方使用紧凑的真实系统式患者上下文：

```text
张三  男 · 24 岁
门诊号 OPD-26020718   耳鼻喉科门诊   门诊   2026-02-07
                                                    模拟演示数据
```

`张三` 是明确的模拟患者姓名；`模拟演示数据` 保留为小号边界说明，不写“示例患者”、不堆叠英文警告，也不暗示连接了真实临床系统。

问诊控制台采用两列：

```text
问诊记录                                      问诊摘要
录音输入中 · 模拟演示                           主诉 / 现病史 / 诱因 / 既往史
▦▦▦▦▦▦
▦▦▦▦▦▦        医生 / 患者转写行              相似病例（最多两条）
```

### 录音方格

- 使用 12 个小方格组成采集缓冲区；
- 一枚小的青绿色录音点缓慢闪烁；
- 方格以柔和的青绿色亮度波移动，表示“模拟录音输入”；
- 用户不需要点按就能理解它是问诊采集状态；
- 渐变只允许出现在这些方格中，用于表达输入强度；页面、卡片、导航和背景不得使用装饰性渐变；
- `prefers-reduced-motion: reduce` 下方格显示稳定的静态信号，录音点不闪烁。

转写内容可按较慢节奏逐行出现或稳定显示完整记录；动效不得阻碍阅读，也不得假称正在调用模型或采集真实麦克风。

## 恢复参与流程

### 01 问诊

- 保留转写、摘要和最多两条相关病例；
- 把录音方格和“录音输入中 · 模拟演示”置于转写区顶部；
- 所有可见标签、患者/医生角色、摘要字段和说明均使用中文。

### 02 开检查

恢复原有参与行为：

- 搜索或筛选检查项目；
- 勾选模拟检查项目；
- 点击“检查开单一致性”；
- 以弹窗或就地结果呈现模拟的冲突与遗漏提醒；
- 用户可以返回修改选项后再次检查。

这是本演示最重要的参与点。提醒必须标为“模拟规则提示”，医疗风险、冲突和优先级使用文字及有限红色表达；不把结果包装成医疗建议。

### 03 查结果

- 保留结构化异常条目和原始报告图片；
- 用中文呈现名称、数值、状态和“模拟报告”；
- 不写长篇医学解释、诊断结论或外部医学来源列表。

### 04 写病历

恢复原有参与行为：

- 由前序模拟信息生成病历草稿；
- 用户可编辑文本；
- 恢复“复制病历”“打印病历”“导出病历”三个动作；
- 所有动作只在浏览器本地生效，不保存、不发送、不接入临床系统；
- 用简短中文说明这一边界。

## 语言与视觉规则

- 所有用户可见产品文本、导航、标题、按钮、状态、表单提示、弹窗和无障碍文字均使用中文；`CISS`、`GitHub` 等专有名称可保留。
- 删除 `Live workflow`、`Live case`、`workflow`、`flow`、`read-only`、`capture buffer`、`deterministic loop` 等英文产品界面词。
- 保留 Clinical White 的白色、冷灰线、近黑文字和唯一青绿色强调；不恢复旧版绿色/紫色大渐变、emoji、厚阴影、圆角彩色 pill。
- 正常项目不以颜色抢眼；红色仅用于真实的模拟冲突或异常状态。
- 不再使用 `00` 总览入口和 16 秒四步骤自动播放。问诊方格是唯一持续动态状态。

## 边界与非目标

- 不接麦克风、不请求媒体权限、不接真实患者数据、不调用模型或医疗 API；
- 不提交真实医嘱，不上传报告，不保存病历；
- 不把静态演示伪装成真实医院系统；
- 不删除已有数据或历史交互逻辑。优先基于当前提交中的原始交互实现恢复功能，再中文化与重构视觉。
